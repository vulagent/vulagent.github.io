What is VulAgent?

VulAgent is a vulnerability-mining tool powered by generative artificial intelligence (AI) that specializes in discovering integer-overflow bugs. During mining, it automatically creates proof-of-concept (PoC) inputs to trigger the flaws and, upon successful activation, produces detailed vulnerability reports. VulAgent’s capabilities are continuously expanded, with support for additional vulnerability classes planned for future releases.

Overview

As shown below, ToolName takes as input a potential bug location and its enclosing function, and automatically produces either a Proof-of-Concept (PoC) that triggers the bug or a justification showing that the bug is not exploitable. This design mirrors how vulnerability validation is typically decomposed in practice and prevents LLMs from conflating context understanding with testcase synthesis. The workflow consists of two major stages.
(1) Testcase Generation. For each target function F₀, ToolName retrieves its callers (F₁, F₂, F₃, …) and performs rule-based pruning to remove evidently safe callers, followed by rule-based slicing to retain only statements relevant to the potential overflow. The resulting sliced functions form the vulnerability contexts, which are ranked by the Code Context Ordering module to identify the most suspicious path. The top-ranked context is then fed into the LLM-based Reasoning module, where the model recognizes functionality, locates key variables, and decides subsequent actions. Guided by the reasoning results, the agent interacts with external tools through the Tools Call interface: a "Code Browser" supplements missing code context, and a "Code Runner" executes candidate testcases that are validated by a "Checker". Failed attempts trigger refined reasoning, forming an iterative reasoning–execution loop.
(2) PoC Generation. Once a testcase passes the "Checker", it enters the PoC generation loop. The LLM mutates and re-executes the testcase until a crash or incorrect behavior is observed, at which point the testcase is finalized as a valid PoC. If all mutations are exhausted without success, ToolName returns a reasoned explanation of non-exploitability and hands control back to the testcase generation stage to initiate a new round of testcase generation.
This design combines static analysis with an adaptive LLM reasoning process tailored to integer overflow vulnerabilities, forming a closed loop that continuously refines hypotheses, executes concrete tests, and validates results, ultimately enabling automated and reproducible confirmation of integer overflow bugs in real-world C projects.
